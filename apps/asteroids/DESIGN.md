# 한결소행성 — 구현 설계 초안

2026-11-15. 사용자 요청: 태양계의 실제 축척 궤도와 시간별 소행성 움직임을 저비용 3D로 표시하고 SPHEREx 관측과 비교한다. 독립 작업 경로는 `한결/한결소행성`. 이 문서는 2026-11-15 사용자 승인 후 구현했다. 실행과 검증은 README.md와 docs/VALIDATION.md를 참고한다.

## 선택한 요구와 제안하는 구현

사용자 요구: 위치·궤도·시간·이름만 사용한다. 개별 물성 분석은 가져오지 않는다. 소행성은 원 대신 네 종류의 무작위 암석이다. 태양계에서 SPHEREx 시점으로 자연스럽게 전환한다. 성능을 최우선으로 한다.

구현자 제안: TypeScript + Three.js + Vite의 독립 웹 앱, Python 오프라인 데이터 준비 도구. 기존 지호 분석기 결과를 읽되 기존 프로그램은 수정하지 않는다. 19개 기존 대상이 초기 범위이며 모두에 관측 영상이 준비되었다고 가정하지 않는다. 관측이 검증된 Eros로 첫 연결을 완성하고 나머지 대상에 확장한다. 원격 자동 배포나 기본 브랜치 변경은 범위 밖이다. macOS/Windows 실행 안내와 로컬 미리보기를 제공한다.

## 접근 비교

1. 권장: 관측·궤도·미리보기를 사전 가공하여 정적 번들로 재생. 최초 데이터 준비 시간이 들지만 재생 중 네트워크와 분석 부하를 없애고 출처를 고정할 수 있다.
2. 실행 때마다 JPL/IRSA 조회: 새 자료에 즉시 접근하지만 대기·서비스 제한·장애로 재생 품질이 흔들린다. 선택적 데이터 갱신 명령으로만 제공한다.
3. 기존 Streamlit 분석기에 3D 추가: 과학 분석 통합은 쉽지만 고빈도 카메라·시간 상호작용을 독립 GPU 장면으로 관리하기 어렵다.

사용자가 1번 접근을 승인했다.

## 화면과 이동

한국어 UI. 중앙 태양계, 왼쪽 이름 검색/목록, 오른쪽 실제 영상 비교, 하단 UTC 타임라인과 재생/속도/이전·다음 관측. 선택 소행성의 궤도만 강조하고 다른 궤도는 기본 숨긴다. 선택되지 않은 라벨은 생략한다.

태양계 공간은 선형 AU 축척. 천체 표식의 크기는 시인성을 위한 확대이며 안내한다. 태양·8행성·선택 데이터에 있는 소행성의 위치를 실제 천체력으로 표시한다. 네 암석 계열은 둥근 다면체/길쭉한 암석/납작한 암석/각진 암석. 안정적인 ID 해시로 계열과 크기 변형을 결정하며 실제 형상이나 분류를 뜻하지 않는다. 위치·궤도 외 물성은 UI에 전달하지 않는다.

카메라는 태양계 전체 → 선택 천체 주변 → SPHEREx 관측 방향으로 전환한다. 축척이 매우 다른 마지막 전환은 단순 카메라 이동만 강제하지 않고 관측 패널 크로스페이드를 함께 쓴다. 중단 가능한 전환, reduced-motion, 선택 변경 시 이전 요청 취소를 제공한다. 관측 모드의 기본값은 실제 촬영 시각에 정지. 사진은 이산 관측이며 사진 사이를 보간하지 않는다. 연속 시뮬레이션과 실제 관측 프레임 재생을 분명히 구분한다.

## NASA 데이터 연결

SBDB 공식 식별자와 별칭을 내부 키로 보존하고 UI에는 이름만 표시한다. 기존 MOST 검색 목록과 stage1/stage2 CSV를 가져온다. SPHEREx 개별 DR1/QR3 영상을 사용하며 전천 합성 지도를 이동체 사진으로 사용하지 않는다. 원본/릴리스/조회 파라미터/시각/체크섬을 기록한다. 필요한 좌표 주변의 작은 FITS cutout만 받고 IMAGE·FLAGS·WCS·노출 시간을 검사한다. 한 관측 시각의 여러 검출기 영상은 그룹화하되 개별 영상과 파장을 유지한다.

목록 존재, 검출기 내부, 측광됨, 위치 확인됨, 불량/미확인은 별도 상태다. 기존 measured_ra/dec가 강제 측광의 예상 좌표일 수 있으므로 필드 존재만으로 검출을 확정하지 않는다. SNR·유효 픽셀·포화·피팅·위치 잔차와 재중심화 성공 상태를 판정에 사용하고 기준을 메타데이터에 저장한다. 기준을 통과하지 못하면 관측 자료만 제공하고 확인된 점을 표시하지 않는다.

## 좌표와 정합

태양계: Horizons VECTORS, 태양 중심, ICRF/J2000에 대한 명시된 기준면, AU 단위, 기하학적 위치. 원본 시간계와 변환을 보존하며 내부 궤도 시간은 TDB, 사용자 시간은 UTC. 행성과 소행성 모두 동일한 기준을 적용한다. 위치·속도 샘플의 보간 오차를 별도 Horizons 시각으로 검증하며 급격한 근접 통과는 간격을 줄인다. 범위 밖 외삽은 금지한다.

영상: Horizons OBSERVER의 SPHEREx 중심 `500@-163182`, 실제 노출 중간 시각을 사용한다. 영상 WCS의 좌표계와 Horizons의 astrometric/apparent 방향 정의를 검증하고 광행시간을 포함한 관측 방향을 사용한다. 태양 중심 기하학 벡터의 단순 투영을 영상 정합의 기준으로 쓰지 않는다. 광행시간 때문에 수신 시각의 기하학 위치와 사진의 방출 시각 위치가 다를 수 있음을 다룬다.

WCS로 예측 RA/Dec를 픽셀 좌표로 옮긴 위치가 최종 정합 기준이다. 이미지 orientation·flip·crop 변환을 동일하게 적용한다. 태양계 장면과 관측 장면은 같은 대상·시각을 공유하지만 관측 투영은 별도 계산한다. 실제 이미지에서 소행성은 분해되지 않을 수 있으므로 암석 실루엣 일치나 임의 수동 보정을 주장하지 않는다. 영상 위 기본 표식은 예측 중심과 측정 중심, 잔차(픽셀/arcsec). 확대 암석은 설명용이며 원본과 정확한 형태 일치를 뜻하지 않는다. 관측 장면 데이터가 준비되지 않으면 SPHEREx 모드가 준비되지 않았다고 표시한다.

## 데이터 계약

manifest: 버전·기간·좌표/시간 정의·대상 목록·출처·파일 크기/해시.
초기 재생 기간은 가져온 유효 관측 목록 전체의 최소~최대 노출 중간 시각으로 결정한다. 초기 선택 시각은 Eros의 첫 사용 가능한 관측이다. 모든 천체 벡터는 이 공통 기간을 포함하며, 화면의 궤도선은 이 기간의 이동 경로로 표시한다. 공전 한 바퀴 전체나 기간 밖 예상 궤도를 임의로 덧그리지 않는다. 추후 기간 확장은 별도 데이터 준비 작업이다.
object: 안정 ID·이름·표현 seed·벡터 파일 경로.
ephemeris: epoch TDB·XYZ·속도·단위·기준면·원점·샘플/보간 오차.
observation: object ID·exposure ID·detector·release·UTC/MJD 시작/중간/끝·파장·이미지/원본 URL·WCS 또는 검증된 투영 파라미터·예측/측정 픽셀·정합 상태·품질 이유.
과거 실행을 덮어쓰지 않는 불변 번들로 관리한다. 19개 결과가 모두 관측 확인 상태라는 가정은 하지 않는다.

## 성능과 장애 처리

네 계열 공유 저폴리 지오메트리, InstancedMesh, 공유 재질, 그림자/후처리/고해상도 표면 텍스처 없음. 초기 DPR 최대 1.5, 저성능 모드 1.0. 천체력은 typed arrays로 한 번 로드하고 애니메이션 프레임마다 네트워크·JSON 파싱·React 상태 갱신을 하지 않는다. 선택 궤도만 고정 최대 정점 수로 표시한다. 저해상도 관측 미리보기부터 표시하고 원본 분석은 별도 실행한다.

정지·숨김 탭에서는 렌더링 중단, 카메라 조작/전환 중에만 필요한 프레임 요청. 관측 이미지 GPU 캐시는 최대 8장 또는 64MB 중 작은 한도, LRU 해제. 이미지 동시 요청 최대 2개, 이전·다음만 미리 받기. 요청 세대 ID와 AbortController로 늦은 응답이 새 선택을 덮지 못하게 한다. 재시도는 제한하고 이전 유효 프레임을 유지한다. WebGL 손실·데이터 없음·네트워크 실패에는 복구 안내. 서비스 응답 실패를 모조 데이터로 대체하지 않는다.

JPL은 순차 요청·캐시·백오프·식별 User-Agent, IRSA도 제한된 동시성. 브라우저 재생은 사전 준비된 데이터로 동작한다. 데이터 갱신 실패와 이미 준비된 앱 재생을 분리한다.

## 검증과 완료 조건

1. 실제 데이터의 UTC/TDB, 원점·축 변환, 보간, WCS 투영에 대한 수치 검사. 관측 시각의 투영 구현 오차 목표 0.1픽셀 이내. 영상 실측과의 잔차는 별도 출력하며 0을 보장하지 않는다.
2. Eros에서 둘 이상의 서로 다른 촬영 시각에 실제 이미지·예측 위치·측정 상태를 연결. 불량 점과 검출 미확인을 숨기지 않는다.
3. 19개 실제 대상 전체 선택·시간 이동·관측 선택·빠른 연타·끝 시각·범위 밖·빈 데이터·서비스 실패 검사.
4. 목표 성능: 시험한 컴퓨터/브라우저/화면 크기를 기록하고 기본 모드 프레임 p95 33ms 이하, 가능하면 16.7ms. 카메라 전환·재생 중 긴 작업과 메모리 증가를 측정한다. 1,000개 렌더링 부하 fixture는 과학 데이터와 분리하고 제품에 가짜 소행성을 섞지 않는다.
5. 100회 대상/영상 전환 후 캐시가 한도 내에 유지되고 GPU 리소스를 해제. 숨김 탭 정지 및 복귀 확인.
6. 타입 검사·수치 단위 테스트·브라우저 시나리오·프로덕션 빌드 완료. 실패·미검증 항목과 실제 성능 수치를 README에 남긴다. 모든 기기에서 무오류·무지연이라고 표현하지 않는다.

## 구현 순서

승인 후 데이터 추출/좌표 검증 → 저폴리 태양계/시간 재생 → WCS 관측 정합 → 카메라 전환/취소/캐시 → 성능·브라우저 검사 → 실행 안내. 화면에서 보는 관측 영상과 JPL 모델의 시각 대응을 검증하는 것이 완성 기준이다.

설계 독립 검토: 재생 기간과 궤도선의 의미를 명시하라는 의견을 반영했다. 그 외 구현 계획을 막는 중요 미결정 사항은 없다는 검토를 받았다. 사용자 승인을 받아 구현했다.
